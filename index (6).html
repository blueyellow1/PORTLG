Team Wilkris  ·  Portaldot V3 Testnet

The problem

Sensitive actions need a say in when they run

Users need better control over when protected smart-contract actions can execute. Wallet interfaces and contract-level controls should work together.

Visibility

Alerts and warnings tell a user something is wrong. They do not decide whether an action runs.

Control

A protected operation needs a clear way to be suspended when execution should stop.

Verifiability

The control should live in the contract, so its state and history can be inspected on-chain.

PORTLG addresses one specific control. It does not claim to solve every blockchain security problem.

The solution

PORTLG Wallet: a wallet interface with an owner-controlled guard

A wallet interface combined with an owner-controlled smart-contract protection mechanism on Portaldot V3 Testnet.

Wallet connection

Connect MetaMask and see which account is in use.

Network validation

The interface checks the network and gives feedback when it is not Portaldot V3 Testnet.

Balance and transactions

View the tPOT balance and prepare supported transactions.

MetaMask stays responsible for private keys and for signing every transaction.

Core feature

Protected Action: the contract decides when it runs

protectedAction() executes when the contract is not paused. The owner calls pause() to block it and unpause() to restore it.

How it works

From wallet to verified result in five steps

STEP 1

The user connects a wallet.

STEP 2

The wallet interacts with Portaldot V3 Testnet.

STEP 3

The owner controls the contract's pause state.

STEP 4

Protected Action checks the contract state before it runs.

STEP 5

Transaction results can be verified on the blockchain explorer.

Technology

Five pieces, each with one job

InterfaceWallet interface

Shows network, balance and supported actions.

WalletMetaMask

Holds private keys and signs transactions.

ContractPORTLGuardLite

Stores the paused flag and enforces Protected Action.

ChainPortaldot V3 Testnet

Executes and records every transaction.

ProofOn-chain verification

Receipts and events can be checked on the explorer.

Private keys never leave the user's wallet. The interface prepares transactions; MetaMask asks the user to review and sign.
